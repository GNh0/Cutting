# Cutting

개인용 **판재 절단 최적화 웹사이트**입니다. 설치·로그인·계산 서버 없이 브라우저에서 실행합니다.

**웹사이트: [gnh0.github.io/Cutting](https://gnh0.github.io/Cutting/)**

## 사용법

처음 접속하면 절단 부재와 보유 원판은 빈 상태로 시작합니다. 예제는 `예제 데이터 불러오기` 또는 `예제로 시작하기`를 눌러 불러옵니다. 이전에 입력한 작업이 있으면 자동 복원하며, `새 프로젝트`로 빈 작업을 시작할 수 있습니다.

1. 절단 부재 표의 한 행에 가로·세로·수량과 **두께·재질(필수)**, 제조사·LOT(선택)을 입력합니다.
2. 보유 원판도 같은 표 형태로 실제 원판 조건과 재고 수량을 입력합니다. 두 표 모두 좌우·상하 스크롤을 지원하며 이름 열과 열 제목을 고정합니다. `···`에서 결 방향을 지정합니다.
3. 최적화 설정에서 **계산식 버전**을 선택하고 톱날 두께와 원판 가장자리 여유를 설정한 뒤 **최적 배치 계산**을 누릅니다.
4. 배치도·절단 순서·미배치 부재·상세 통계를 확인합니다.
5. 결과 상단 오른쪽의 SVG·PNG·PDF에서 저장합니다. SVG·PNG는 선택 원판을 저장하며, PDF는 선택 원판 또는 전체 원판의 배치도와 절단표를 브라우저 인쇄 창에서 저장합니다.

원판 그룹당 한 장만 사용, 회전 허용, 조건에 맞는 원판 선택, 결 방향 유지, 부재별 밴딩 표시, 계산식·탐색 수준별 후보 탐색을 지원합니다. CSV·엑셀 셀 붙여넣기, 결과 CSV, JSON 프로젝트 백업, 브라우저 보관함도 제공합니다.

상세 통계의 잔재 목록은 같은 가로·세로·두께·재질·제조사·LOT·결 방향별로 수량과 총면적을 합산하며, 원판별 잔재 위치를 확인할 수 있습니다. `잔재로 다음 작업`에서도 같은 규격의 잔재와 보유 재고 수량을 합칩니다. 가로·세로가 뒤바뀐 치수는 결 방향 보존을 위해 별도로 유지합니다.

단위는 mm/cm/m/inch입니다. 단위를 바꿔도 실제 크기는 유지됩니다. CSV는 현재 표시 단위로 읽습니다. **두께·재질은 원판과 일치해야 합니다. 부재에서 제조사·LOT을 비워 두면 해당 항목을 제한하지 않으며, 입력한 항목만 정확히 일치해야 합니다.** 예: 제조사만 입력하면 해당 제조사의 모든 LOT을 후보로 비교합니다. LOT만 입력하면 제조사에 관계없이 그 LOT만 허용합니다. 원판의 빈 제조사·LOT이 입력된 요구 조건을 대신 충족하지는 않습니다. 문자열의 앞뒤 공백만 제거하며 대소문자를 구분합니다. 이 조건은 끌 수 없습니다. 두께는 표시 단위로 입력하고 내부에서는 mm로 저장합니다. 기존 프로젝트에 두께가 없으면 입력 후 계산해야 합니다. 결 미지정은 자유 방향입니다. 엣지밴딩은 위치 표시와 필요 길이 계산용이며 치수를 차감하지 않습니다.

입력은 요청 조건별로, 결과는 실제 사용 원판의 네 항목별로 그룹을 구분합니다. 사용한 모든 원판을 아래로 이어 보여주며, 원판 선택은 해당 카드로 이동합니다. 기본 배율의 캔버스 내부 세로 스크롤은 없습니다. 절단 순서는 넓은 화면에서 캔버스 옆, 작은 화면에서는 바로 아래에 표시하며 행 선택은 캔버스 위치를 바꾸지 않고 절단선을 강조합니다.

## 개발 실행

Node.js 22 이상 권장. 사이트 자체는 외부 패키지·CDN 의존성이 없습니다.

```sh
npm start
# http://127.0.0.1:4173
npm test
npm run version-assets # 배포 전 변경 파일의 공통 캐시 버전 갱신
npm run check
```

ES Modules와 Web Worker를 사용하므로 `index.html`을 파일로 직접 여는 대신 HTTP(S) 주소로 실행합니다. GitHub Pages는 `main` 브랜치 루트에서 제공합니다. `.nojekyll`이 포함되어 별도 빌드가 필요 없습니다.

## 계산 방식

계산식 버전은 `Cutting v1`과 `Smart2D 분석 v1 (실험)` 중 선택합니다. 기존 프로젝트와 새 프로젝트의 기본값은 Cutting v1입니다. 선택한 버전은 프로젝트 JSON·자동 저장에 보관하며, 결과와 PDF·SVG·CSV에도 실제 계산에 사용한 버전을 남깁니다. 선택만 바꾸면 이전 결과 안내가 나오며 재계산해야 새 버전의 배치를 볼 수 있습니다. 알 수 없는 버전 ID를 다른 버전으로 임의 대체하지 않습니다.

Smart2D 분석 v1은 설치된 Smart2DCutting 3.5 Demo에 대한 REA·Ghidra 조사와 공식 도움말의 방향 3종 × 수준 3종 계약을 참고한 독립 휴리스틱입니다. 내부 수식을 그대로 복구한 엔진이나 원본 실행 결과와 같은 엔진을 뜻하지 않습니다. 그룹당 빠르게 9개·균형 36개·정밀 144개 후보를 탐색합니다. 높은 탐색 수준은 낮은 수준 후보를 포함하며, 9·36·144개 경계에서 최선 배치의 물리 절단 계획을 비교합니다. 기존 입력에서 지원하지 않는 Smart-Trim·사전 절단·밴드 두께 차감은 추가하지 않습니다.

[복합 조건 36개·108회 버전 비교](docs/version-comparison.md)에서는 자재 기준으로 기존 v1이 77회, 새 버전이 31회 우세했습니다. 전체 조건에 대한 보편적인 우열을 증명하는 수치는 아니며, 우선순위와 입력에 따라 결과가 바뀝니다. 기본값은 기존 v1로 유지합니다. [Smart2D 분석 근거와 한계](docs/smart2d-analysis.md)를 함께 확인하세요.

Cutting v1은 독립 구현한 길로틴 휴리스틱입니다. 한 번의 절단은 현재 조각을 끝까지 가로지릅니다. 네 탐색 계열을 함께 실행하는 하이브리드입니다. 제조사·LOT을 지정한 부재와 미지정한 부재가 같은 원판 재고를 후보로 가지면 함께 탐색하여 재고를 중복 계산하지 않습니다. 지정 항목과 후보 수가 적은 부재를 먼저 고려하고, 일부 배치 후보는 다른 요청이 필요로 하는 재고 수량도 고려해 원판을 선택합니다. 결과와 잔재는 실제 사용한 원판의 두께·재질·제조사·LOT으로 구분합니다. 여러 부재 정렬, 공통 치수별 띠 배치, 큰/작은 원판 우선, 잔여 영역 점수, 가로/세로 분할을 비교합니다. 기본 순서는 미배치 수량, 미배치 면적, 사용 원판 면적, 재사용 잔재 점수, 절단 횟수, 총 절단 길이입니다. 잔재 점수는 재사용 가능 총면적 + 최대 재사용 잔재 면적의 10%이며, 두 변이 최소 폭 설정 이상인 잔재만 집계합니다. `큰 잔재 우선`은 총면적 점수 대신 최대 잔재부터 비교합니다. `절단 횟수 최소` 설정은 원판 면적보다 절단 횟수를 먼저 비교합니다.

배치를 먼저 선택하고 부재 위치·회전·사용 원판을 고정한 뒤, 공통 절단선을 고려해 절단 트리를 다시 탐색합니다. 원판당 부재 2~48개에서 최대 512개 상태를 탐색하며, 대체 계획을 찾지 못하거나 48개를 넘으면 원래 절단선을 유지합니다. 절단 횟수를 먼저 최소화하고 재사용 잔재 조건을 지키는 후보들에서, 절단 길이와 다음 시작점까지의 이동거리를 합한 총 진행거리를 줄입니다. 총거리까지 같으면 방향 전환을 줄입니다. 절단 길이만 짧다는 이유로 더 긴 동선의 계획을 우선하지 않습니다. 이전 절단 트리 전략도 후보로 남깁니다. 6개 이하 부재는 각 사각형에서 비용이 같은 대안 트리를 최대 24개 추가 보존합니다.

각 트리에서 부모 절단을 먼저 실행하는 조건을 지키며 순서를 비교합니다. 절단 12회 이하이고 20,000개 순서 상태 안에서 끝나면 해당 트리의 최단 순서를 구합니다. 그 밖에는 폭 24의 제한 탐색(80회 초과는 폭 1)을 사용하고 이전 정렬 순서도 후보로 보존합니다. 전체 배치·절단 트리에 대한 수학적 최적해를 보장하지 않습니다. 위치 이동거리는 원판 좌상단의 사용 가능 영역에서 시작해, 표시된 가로→·세로↓ 절단의 끝점에서 다음 시작점까지 직선 거리 합계로 계산합니다. 총 진행거리는 이 위치 이동과 절단 길이의 합입니다. 작업물 운반·회전 시간과 장비별 복귀 동작은 모델에 포함하지 않습니다. 계산 버튼은 프로젝트 행에 있으며 이 행 전체가 스크롤을 따라갑니다.

절단선의 오른쪽/아래쪽에 톱날 폭을 확보합니다. 원판과 정확히 일치하는 경계에는 불필요한 톱날 여유나 절단을 추가하지 않습니다. 가장자리 여유는 네 면의 사용 불가 영역으로, 정재단 절단은 표의 횟수·길이에서 제외됩니다. 이용률은 부재 면적 / 사용 원판 전체 면적입니다. 남는 면적에는 톱날과 가장자리 여유가 포함됩니다.

휴리스틱이므로 수학적 최적해를 보장하지 않습니다. 부재 수량 합계와 각 입력 행은 최대 1,000입니다. 이 제한은 작업 크기 제한이며, 계산 실행 횟수 제한은 없습니다.

## 데이터 보관

입력값은 계산 서버에 전송하지 않고 브라우저의 `localStorage`에 저장합니다. 기기/브라우저별로 별도 보관하며 자동 동기화하지 않습니다. 브라우저 데이터를 지우면 보관함도 삭제되므로 JSON 파일 백업을 권장합니다. 사이트 접속 자체는 GitHub Pages를 이용합니다.
