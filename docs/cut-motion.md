# 절단 횟수와 동선 공동 비교

기준 버전은 `87b5c982ada88935bee91baf95a26ab3809da290`이며, 최종 복합 측정의 엔진은 `50a14cf`에 보관했습니다. 이후 배포에서는 화면·계산 모듈의 캐시 버전 URL만 추가했습니다. 버전 쿼리를 제외한 계산 소스가 측정 커밋과 같음을 확인했습니다. 배치 알고리즘이 고른 원판·부재 좌표·회전·미배치 수량을 고정하고, 이전 버전과 이번 절단 계획을 같은 입력으로 실행했습니다. 기존의 단순 방향별 정렬을 거리 기반 순서 탐색으로 바꾸고, 거리까지 고려해 대안 절단 트리도 비교합니다.

## 비교 기준

절단 횟수를 먼저 최소화합니다. 재사용 잔재 조건을 지키는 후보들에서 **총 진행거리 = 절단 길이 + 다음 절단 시작점까지의 위치 이동거리**를 줄이고, 총거리까지 같으면 방향 전환을 줄입니다. 절단 길이가 조금 짧아도 위치 이동이 훨씬 길어지는 계획을 우선하지 않습니다.

한 번의 절단은 현재의 직사각형 조각 전체를 가로지릅니다. 부모 절단이 완료된 뒤 자식 절단을 실행합니다. 분리된 조각을 다시 붙이거나 포개서 한 번에 자르는 작업은 가정하지 않습니다. 원판 좌상단 사용 영역에서 시작하며, 표에 표시한 가로→·세로↓ 방향으로 진행합니다. 절단 사이의 이동은 원판의 원래 좌표에서 직선 거리로 측정하고, 마지막 절단 뒤 원점 복귀는 포함하지 않습니다.

장비별 가감속·복귀 동작·방향 변경 시간과 작업물 운반·회전 시간은 모델에 포함하지 않습니다. 따라서 거리 개선율을 실제 작업시간 개선율로 바꾸어 설명하지 않습니다.

## 크롬에 입력된 1,610 × 610 mm 사례

[재현 입력·이전 절단표·최종 절단표·소스 해시](cut-motion-example.json)를 보관했습니다. 요청 부재는 11개이며, 사용 가능한 원판 한 장에 배치된 6개를 대상으로 비교했습니다. 나머지 5개는 두 버전 모두 미배치입니다.

| 항목 | 이전 버전 | 이번 수정 |
|---|---:|---:|
| 사용 원판 / 배치 부재 | 1장 / 6개 | 1장 / 6개 |
| 절단 횟수 | 8회 | 8회 |
| 절단 길이 | 5.281 m | 5.351 m |
| 절단 사이 위치 이동 | 6.7174 m | 3.1595 m |
| 총 진행거리 | 11.9984 m | 8.5105 m |
| 방향 전환 | 3회 | 3회 |

총 진행거리는 **29.07%**, 위치 이동은 **52.97%** 줄었습니다. 부재 위치와 이용률은 같습니다. 절단 길이는 70 mm 늘지만 전체 진행거리는 약 3.49 m 줄어듭니다.

독립 검증 코드 `tests/cut-oracle.mjs`는 이 고정 배치에서 부재 경계와 톱날 폭으로 가능한 절단 트리를 제한 없이 열거합니다. 최소 8회인 트리 19개와 부모 선행 조건을 지키는 순서 659개를 전부 비교했고, 최종 코드가 같은 최소 횟수·최단 총거리 결과를 냈습니다. 이 사례의 전수 비교 결과를 일반 대량 입력의 전역 최적해 보장으로 확대하지 않습니다.

기존 표의 7·8번 가로선을 합칠 수는 있습니다. 그러려면 가운데 세로선을 자르기 전에 가로선을 잘라야 하고, 그 뒤에는 위·아래 조각의 세로선을 각각 잘라야 합니다. 이 대안도 총 8회입니다. 이미 세로로 분리한 두 조각의 가로선을 단순히 하나로 늘리고 행 하나를 삭제하는 계획은 물리적 절단 재생 검사에서 실패합니다.

## 복합 조건 1,000건

[최종 측정 원본](cut-motion-backtest.json)은 시나리오 인덱스 `11000000..11000999`와 각 소스 SHA-256을 포함합니다. 도중 시험 결과를 더해 독립 조건 수를 부풀리지 않았습니다. 최종 실행 안에서 물리 조건 지문 1,000개가 모두 달랐습니다.

- 부재 24~48종, 총 수량 56~1,000개, 원판 9~12종.
- 두께·재질·제조사·LOT, 제조사/LOT 미지정 요청, 결 방향·회전 제한, 소수 치수, 톱날 폭, 가장자리 여유, 재고 부족, 원판 그룹당 한 장 제한.
- 빠르게·균형·정밀 설정과 면적·잔재·절단 우선 설정을 포함합니다.
- 대량 조건 300건, 그중 1,000개 부재 조건 100건.
- 총 22,004장. 원배치·이전 절단·최종 절단에 대해 물리 조각 재생·면적 보존·치수·수량·재고·재질 검사 **3,000회 통과**.

| 합계 | 이전 버전 | 이번 수정 |
|---|---:|---:|
| 절단 횟수 | 290,154회 | 290,154회 |
| 절단 길이 | 212,872.580 m | 213,118.819 m |
| 위치 이동거리 | 262,245.999 m | 203,487.726 m |
| 총 진행거리 | 475,118.580 m | 416,606.546 m |
| 방향 전환 | 71,334회 | 159,722회 |

이 표는 전체 조건의 합계입니다. 총 진행거리 **12.32%**, 위치 이동 **22.41%** 감소입니다. 절단 길이는 **0.116% 증가**했고 방향 전환도 늘었습니다. 이번 목적 함수는 최소 절단 횟수와 총거리를 우선하므로, 방향 전환 횟수나 장비 작업시간까지 동시에 최소라고 주장하지 않습니다.

22,004장 모두 절단 횟수가 이전과 같았으며 증가한 원판은 없습니다. 절단 횟수와 재사용 잔재 총면적·최대 면적이 모두 같은 21,436장에서는 총거리 개선 20,365장, 동일 1,071장, 악화 0장이었습니다. 나머지 568장은 잔재 분할 결과가 달라 같은 잔재 조건의 거리 승패 집계에서 제외했습니다.

## 탐색 범위와 재실행

절단 트리 재구성은 부재 2~48개, 원판당 사각형 상태 512개 한도입니다. 이전 트리 전략을 후보로 유지하며, 6개 이하 부재에서는 동률 대안을 사각형당 최대 24개 더 보존합니다. 순서 탐색은 선택된 트리의 절단 12회 이하·20,000개 상태 이내에서 정확 탐색, 그 밖에는 제한 탐색을 사용합니다. 큰 문제의 전역 최적성을 보장하지 않습니다.

```sh
npm run check
npm test
node tools/cut-motion-backtest.mjs 1000
```

자동 테스트 59개와 최종 복합 검증을 통과했습니다. 백테스트는 Web UI와 별개인 Node 작업 스레드 4개로 실행했고 종료 시 모두 정리합니다. 기준 커밋의 소스를 Git에서 직접 읽으므로 해당 커밋이 로컬 저장소에 있어야 합니다.

## 결과 저장 UI

SVG·PNG·PDF를 결과 상단 오른쪽 한곳에 모았습니다. SVG·PNG는 표시된 선택 원판을 저장합니다. PDF는 선택 원판 또는 전체 원판을 고르고, 브라우저 인쇄 창에서 ‘PDF로 저장’을 선택합니다. 배치도와 해당 절단 순서를 함께 출력하며, 미배치 목록은 전체 출력에만 포함합니다.
