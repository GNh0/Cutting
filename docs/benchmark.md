# 백그라운드 알고리즘 검증

이 문서는 두께·제조사·LOT 그룹 기능 추가 전 엔진의 고정 스냅샷 측정 기록입니다. 현재 버전은 각 그룹을 독립 계산하며 후보 횟수는 그룹 수에 따라 늘어납니다. 아래 수치를 현재 그룹 기능의 전체 검증 수치로 해석하면 안 됩니다. 현재 그룹 일치·재고·잔재 이월은 `tests/materials.test.mjs`에서 별도로 검증합니다.

웹페이지·원본 계산 서버를 사용하지 않고 Node.js Worker Threads 4개로 계산 엔진만 실행했습니다. 튜닝 단계 70,000개와 별도의 최종 검증 100,000개를 실행했으며, 두 단계 합계 배치 후보 탐색은 40,800,000회입니다. 이는 **4천만 가지 독립 입력**이라는 뜻이 아닙니다.

## 최종 검증 규모

- 생성 시나리오: **100,000개**
- 실질 입력을 SHA-256으로 중복 제거한 조건: **99,663가지**
- 알고리즘 실행: **400,000회**
- 완전한 배치 후보 탐색: **24,000,000회**
- 최종 결과 절단 재생·제약 검사: **400,000건**, 오류 없음
- 총 경과 시간: **246.05초**

조건은 정확한 격자, 공통 치수 띠 묶음, 혼합 캐비닛, 복수 원판 규격, 재고 부족, 재질·결 제약, 소수 치수·톱날, 길고 좁은 부재의 8개 계열이며 각각 12,500건입니다. 주로 3~40개 안팎의 부재와 여러 규격·수량의 원판을 사용합니다. 1,000개 부재 상한은 별도 단위 테스트로 검증합니다. 실제 MES·ERP 업무 데이터 성능을 대변하는 표본은 아닙니다.

## 선택한 방식

기존 정렬·분할 48회, 같은 후보의 재사용 면적 평가 48회, 잔재 형태 유도 48회, 확장 포트폴리오 96회를 합쳐 **240개 후보 중 가장 나은 결과**를 선택합니다. 빠름/균형은 각각 30/120개 후보입니다. 기존 후보도 보관하므로 기존 결과가 더 나으면 그것을 유지할 수 있습니다.

기본 비교 순서는 미배치 수량 → 미배치 면적 → 사용 원판 면적 → 재사용 잔재 점수 → 절단 횟수 → 절단 길이입니다. 잔재 점수는 **재사용 가능 총면적 + 최대 재사용 잔재 면적 × 0.1**입니다. 두 변이 모두 100 mm 이상인 잔재를 재사용 가능으로 집계했으며 실제 웹에서는 최소 폭을 바꿀 수 있습니다. 이 가중치는 향후 어떤 부재가 필요할지 모르는 상황의 실용적 절충이며 수학적으로 유일한 최적 목적함수라는 주장이 아닙니다.

## 결과

동일 평가 기준으로 기존 버전 대비 개선 66,053건, 동률 33,947건, 악화 0건이었습니다. 0건이라는 결과는 기존 후보를 유지하며 최종 비교하는 구조와도 관련됩니다. 모든 개별 지표가 동시에 좋아졌거나 전역 최적해를 증명했다는 의미가 아닙니다.

| 전체 합계 지표 | 기존 | 선택 방식 | 변화 |
| --- | ---: | ---: | ---: |
| 사용 원판 면적 | 389,333.989 m² | 388,043.782 m² | **0.3314% 감소** |
| 미배치 부재 | 47,793개 | 46,463개 | **2.7828% 감소** |
| 재사용 가능 잔재 면적 | 147,038.087 m² | 151,393.251 m² | **2.9619% 증가** |
| 절단 횟수 | 2,179,760회 | 2,113,066회 | **3.0597% 감소** |
| 절단 길이 | 1,486,101.479 m | 1,465,895.272 m | **1.3597% 감소** |

최대 잔재 한 장의 면적 합계는 11.5881% 감소했습니다. 총 재사용 가능 면적을 늘리는 대신 한 장의 최대 크기는 줄 수 있는 절충입니다. 큰 부재를 나중에 만들 계획이면 웹의 **큰 잔재 우선**을 선택할 수 있으며, 작업량을 줄이려면 **절단 횟수 최소**를 선택합니다. 따라서 위 평균 수치로 어떤 사용자·어떤 입력에도 우월하다고 말할 수 없습니다.

원본 웹과 직접 비교한 책장 사례는 개선 후에도 원판 1장, 11개 배치, 이용률 69.2669%, 절단 14회·길이 10,494, 잔재 1034×653 / 295×564 / 800×47 / 600×7을 유지합니다.

## 배포 코드 확인

최종 벤치마크 엔진을 해시로 고정해 실행했습니다. 배포 진입점은 추가 **1,000개 새로운 입력**에서 고정된 하이브리드와 결과 전체가 일치했고 절단 재생도 통과했습니다. 실제 통합 호출의 중앙값은 **4.96 ms**, 95백분위는 **13.59 ms**, 최대는 **29.83 ms**였습니다. 이 값은 현재 PC의 해당 합성 입력에 대한 측정이며, 브라우저·대형 작업의 응답 시간을 보장하지 않습니다.

- [최종 집계·계열별 승패·엔진 해시](benchmark-results.json)
- [배포 진입점 검증·실제 시간](production-verification.json)
- 재현 명령: `node tools/benchmark.mjs 100000 acceptance`
- 배포 진입점 확인: `node tools/verify-production.mjs`
