# 계산식 버전 복합 조건 비교

2026-10-23 현재 테스트한 복합 조건에서는 **기존 Cutting v1이 전반적으로 우세**했다. 새 Smart2D 분석 v1이 항상 더 좋은 계산식은 아니다. 기본값은 기존 v1을 유지하고, 새 버전은 별도 실험 버전으로 제공한다.

이 비교는 **Cutting에 등록한 독립 계산 엔진 두 개**의 비교다. 원본 Smart2DCutting 3.5 Demo를 같은 입력으로 실행해 비교한 결과가 아니다. 새 엔진의 근거와 복구 한계는 [Smart2D 분석](smart2d-analysis.md)에 기록한다.

## 실행 조건

- 서로 다른 복합 입력 36개, 입력당 빠르게·균형·정밀 3개 수준: 108회 일대일 비교, 엔진 실행 216회.
- 부재 24~44종, 활성 수량 56~942개, 원판 9~12종. 두께·재질·제조사·LOT 그룹, 제조사·LOT 미지정에 따른 재고 공유, 결 방향, 회전 금지, 소수 치수·톱날 폭·트림, 비활성 행, 그룹당 원판 한 장 제한과 재고 부족을 포함한다.
- 톱날 폭 0.8~5 mm, 트림 0~10 mm. 작업별 원판·절단·큰 잔재 우선순위를 순환한다. 우선순위마다 서로 다른 입력 12개에 대해 탐색 수준 3개를 비교한다.
- 같은 비교에서는 입력·설정·재고가 완전히 같고 계산식 ID만 바꾼다. 실행 순서를 교대로 바꾼다.
- 모든 실행에서 절단선을 실제 조각에 재생하여 절단 가능성, 면적 보존, 중복 부재, 재질·결 방향, 재고 초과와 입력 불변성을 확인했다. 물리 검사 216회 모두 통과했다.

## 우열 판정

미배치 수량, 미배치 면적을 먼저 비교한다. 이후 현재 시스템의 우선순위를 그대로 따른다.

- 원판 우선: 사용 원판 면적 → 재사용 잔재 면적 + 최대 잔재 면적의 10% → 절단 횟수 → 절단 길이.
- 절단 우선: 절단 횟수 → 사용 원판 면적 → 위 잔재 점수 → 절단 길이.
- 큰 잔재 우선: 사용 원판 면적 → 최대 잔재 → 전체 재사용 잔재 → 절단 횟수 → 절단 길이.

원판 크기가 다르므로 장수만으로 판단하지 않는다. 계산 시간은 별도로 표시하며 품질 승패를 바꾸지 않는다. 절단 횟수가 적더라도 부재를 덜 배치했으면 우세로 판단하지 않는다.

## 결과

| 탐색 수준 | 비교 횟수 | Cutting v1 우세 | 새 버전 우세 | 평균 실행 시간: 기존 / 새 버전 |
|---|---:|---:|---:|---:|
| 빠르게 | 36 | 27 | 9 | 244 / 149 ms |
| 균형 | 36 | 30 | 6 | 278 / 354 ms |
| 정밀 | 36 | 21 | 15 | 408 / 602 ms |
| 전체 | 108 | **78** | **30** | — |

동률은 없었다. 기존 버전은 72.2%, 새 버전은 27.8%의 비교에서 설정된 목적함수상 우세했다. 총 배치 수량은 기존 12,639개 / 새 버전 12,514개였다. 이는 서로 다른 탐색 수준 실행을 합산한 수치이며, 실제 한 작업의 생산량이나 독립 표본 108개를 뜻하지 않는다.

| 우선순위 | 기존 우세 | 새 버전 우세 |
|---|---:|---:|
| 원판 우선 | 25 | 11 |
| 절단 우선 | 27 | 9 |
| 큰 잔재 우선 | 26 | 10 |

정밀 수준의 36개만 보면 기존이 4,256개, 새 버전이 4,254개를 배치했다. 새 버전의 총 사용 원판 면적은 약 0.35%, 절단 횟수는 약 2.43% 작았지만 배치한 부재가 2개 적었다. 따라서 이 합계만으로 새 버전이 낭비·절단을 항상 더 줄인다고 해석하면 안 된다.

작업별 차이도 남는다. 정밀·절단 우선인 `complex-23000001`은 양쪽 모두 88개를 배치하고 새 버전이 136회, 기존이 141회 절단해 새 버전이 우세했다. 반대로 `complex-23000004`는 양쪽 모두 67개를 배치하고 기존이 100회, 새 버전이 104회로 기존이 우세했다. 정밀·원판 우선 12개에서는 새 버전이 7회, 기존이 5회 우세했으므로 세부 조건까지 기존 버전이 항상 이긴다는 뜻도 아니다.

결론은 **범용 기본값은 기존 v1을 유지할 근거가 있고, 새 버전은 입력별 대안으로 남길 가치가 있다**는 것이다. 수학적 최적해나 원본 Smart2DCutting 대비 성능을 증명한 결과는 아니다. 실행 시간은 이 PC의 당시 부하에 영향을 받는다.

## 재현

```powershell
npm run benchmark:versions
```

생성기 seed는 `23000000..23000035`이다. [실제 복합 입력](version-benchmark-inputs.json)과 전체 결과·입력 서명·실행 당시 소스 SHA-256을 [version-benchmark.json](version-benchmark.json)에 보관한다. 실행 당시와 최종 계산 코드의 차이는 모듈 캐시 버전 문자열뿐이며 계산 로직이 동일한지 별도로 검증했다. 이후 비교 스크립트의 결과 저장 경로와 불필요한 진행 파일 쓰기만 정리했다.
