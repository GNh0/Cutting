# 원본 직접 비교 기록

원본: https://www.cutlistoptimizer.com/

CSV 업로드나 원본 서버 API 직접 호출 없이, 공개 웹의 부재·원판 표에 수치를 직접 입력하고 Calculate를 실행했습니다. 원본 단위 표시는 Generic이었으며 동일 숫자를 mm 스케일로 해석해 비교했습니다. 원본의 Minimum trim dimension과 Cutting의 가장자리 여유는 모두 0입니다. 목적은 원판 사용량, 배치 수, 절단, 잔재의 비교이며 이미지의 색상 일치를 목표로 하지 않습니다.

| 사례 | 부재 / 원판 / 톱날 | 원본 | 개선한 Cutting |
| --- | --- | --- | --- |
| 정확한 4분할 | 500×500 4개 / 1000×1000 / 0 | 1장, 100%, 3회, 길이 2000 | 동일 |
| 톱날 경계 | 위와 같음 / 톱날 3 | 4장, 25%, 8회, 길이 6000 | 동일 |
| 회전 필요 | 900×600 2개 / 600×900 2장 / 3 | 2장, 100%, 추가 절단 0회 | 동일 |
| 혼합 책장 | 아래 상세 / 2440×1220 / 3 | 1장, 11개 배치, 14회, 길이 10494 | 동일 |

책장 입력: 측판 800×300 2개, 선반 564×300 4개, 상하판 600×320 2개, 뒷판 764×564 1개, 보강대 564×80 2개. 전체 부재 면적 2,061,936, 사용 원판 면적 2,976,800, 이용률 **69.2668637463%**입니다. 원본 화면의 반올림 표시는 69%였습니다.

책장 잔재는 두 결과 모두 회전을 제외하면 **1034×653, 295×564, 800×47, 600×7**입니다. 폭·길이 모두 100 mm 이상을 재사용 가능으로 보면 2개, 총 841,582 mm²이며, 최대 잔재는 675,202 mm²입니다.

첫 구현은 이 책장 사례에서 17회·길이 10873이었고 잔재가 분산되었습니다. 공통 치수별 띠 묶기와 잔재 평가를 추가해 위 결과로 개선했습니다. 90° 보기로 원본의 세로 배치와 비교할 수 있습니다. 절단 순서의 세부 순번까지 같다는 뜻은 아닙니다.

무료 계산 제한에 도달했다는 사용자 확인 후 원본 추가 계산을 중단했습니다. 다음 복합 사례를 입력하는 과정에서는 브라우저 자동화로 원판 숫자가 누적 입력된 것을 발견해 그 결과를 비교에서 제외했습니다. 따라서 **원본에서 확인한 성공 사례는 위 4개**이며, 결·재질 등 나머지 조건까지 원본과 실측 비교했다고 주장하지 않습니다. 이를 보완하는 자체 기하학·대규모 합성 입력 검증은 [benchmark.md](benchmark.md)에 기록합니다. 제한을 우회하거나 유료 계산을 사용하지 않았습니다.

원본 수치와 직접 입력 기록은 로컬 분석 증거에 보관했습니다. 재현 가능한 입력은 [tests/reference-cases.mjs](../tests/reference-cases.mjs)에 있으며, 원본 실측하지 않은 사례는 자체 검증용으로 구분해야 합니다.
